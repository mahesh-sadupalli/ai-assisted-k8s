# Milestone 2 — Containers + Kubernetes + thin observability slice

Full spec lives in `../README.md` → **Milestones → M2**. This is the working checklist.

## Build
- [x] Multi-stage Dockerfile (distroless, ~14 MB) for the control-plane and the sample `hello` service
- [x] Manifests: `Namespace`s, `ResourceQuota/sentinel-quota` (read by the guardrail), RBAC, control-plane `Deployment`/`Service`/`ConfigMap`
- [x] Local cluster via **kind**; the control-plane server-side-applies a `Deployment` + `Service` per request
- [x] **Prometheus** scrapes `/metrics` (RED: `http_requests_total`, `http_request_duration_seconds`) via a `ServiceMonitor`
- [x] **One Grafana dashboard**: RED for the control-plane
- [x] `agent/` v1: `agent pod` / `agent scan` read pod status, events and logs (including the crashed container's) via `client-go`
- [ ] Loki: deferred to M5, where centralized logs are in scope

## Run it
```bash
make up              # kind cluster + images + control-plane
make observability   # kube-prometheus-stack + ServiceMonitor + dashboard
kubectl -n sentinel-system port-forward svc/control-plane 8080:80
kubectl -n monitoring port-forward svc/kps-grafana 3000:80        # admin / sentinel
```

## Notes / evidence (2026-10-30)
- `POST /deployments` for `hello` → `201 status=applied`; `kubectl get pods -n team-a` shows 2/2 Running.
- Over-quota request → `403 ... CPU quota exceeded: 2500m requested, 2000m allowed`. That 2000m comes from the cluster's `ResourceQuota`, not from code.
- Prometheus target `control-plane` is `up`; series per route/code visible; Grafana lists "Sentinel control-plane — RED".
- Injected failure: `kubectl -n team-a set env deploy/hello LEAK_MIB_PER_SEC=8` → pods OOMKilled → `go run ./agent scan team-a`:
  ```
  Severity:         high
  What broke:       hello pod in CrashLoopBackOff, OOMKilled 3 times (exit 137), never ready.
  Likely cause:     In-memory cache grows ~8Mi/s without limit and passes the 64Mi limit: a leak, not a sizing problem.
  Suggested action: Put a size limit or eviction on the cache, or roll back to a known-good image. Raising the limit only delays it.
  ```
